# Code review: 1.0.10 RC (`latest.cpp`) vs 1.0.4 public (`releases/1.0.4.cpp`)

Scope: full unified diff, 410 hunks, +5,778 / -908 lines (36,447 → 41,224 lines).
Line numbers refer to `latest.cpp`. No code was changed for this review.

Main areas changed: the XML theme engine; Tiles/Content layouts; list↔grid morphing;
folder sizes for Size sort/group; status-column glyphs (OneDrive); hidden-extension labels;
slow-click / multi-item rename and the list-matched rename text; the layered tooltip;
drag-and-drop autoscroll; search-term highlighting; compact view; zebra band animation;
pre-sort option removal; extra diagnostics.

Severity: **H** = likely bug, data race or rule violation; **M** = real risk or measurable
cost; **L** = smaller issue or code-quality point. "Verify" means the risk depends on Shell
behaviour that I could not confirm from the code alone.

---

## High

### H1. `PropertyLabel` has an unsynchronized static cache and returns a reference that can dangle
`latest.cpp:19125`, used from Paint at `latest.cpp:24324`.
- `static std::vector<std::pair<PROPERTYKEY,std::wstring>> labels` is read and appended
  with no lock. Explorer runs each frame window on its own thread, and tabs paint on
  their own lanes. Two windows in Content view would race on `emplace_back`, which is UB.
- It returns `const std::wstring&` into that vector. A later `emplace_back` that
  reallocates leaves earlier references dangling. Today's caller does not hold one across
  calls, but the API invites that bug.
- It calls `PSGetPropertyDescription`/`GetDisplayName` from the paint path the first time
  each key is seen.
- Fix: resolve the two labels once per tab, or at init on the owning thread, and store
  them by value in `ViewState`. Alternatively, use an SRW lock and a node-stable container
  such as `std::map`, and return by value.

### H2. `FolderLocation` now makes Shell provider calls on Explorer's STA and widens which folders get the GPU view
`latest.cpp:8803` (new block after the PIDL-prefix walk).
- `SHCreateItemFromIDList` + `IShellItem::GetAttributes(SFGAO_FILESYSANCESTOR|FOLDER|HASSUBFOLDER)`
  run during navigation on the UI thread. The removed comment said "no enumeration,
  attributes, …" on purpose. This conflicts with AGENTS.md: keep cold provider calls off
  the UI thread. Slow namespaces (MTP phones, network locations, cloud roots) can block here.
- The admission heuristic `(attrs & (FILESYSANCESTOR|HASSUBFOLDER)) != HASSUBFOLDER`
  accepts every Shell folder that does not report `SFGAO_HASSUBFOLDER`. That flag is
  advisory, and providers report it inconsistently. This can silently move namespaces
  onto the GPU view: All Control Panel Items, Network, printer or device folders,
  third-party shell extensions. Gallery is excluded by exact PIDL; nothing else is.
- Fix: decide admission on the directory worker, or from attributes Explorer has already
  cached, and gate it with an allow-list or capability check. Do not infer it from
  `HASSUBFOLDER`.

### H3. Diagnostics run regardless of the mod's "Enable logging" option, and one of them makes Shell calls
- `ProbeShellSortState` (`latest.cpp:13633`) runs `GetFolderPath`, `ItemCount`,
  `GetCurrentFolderFlags`, `IColumnManager::GetColumnCount/GetColumns`,
  `IShellView::GetWindow` and `GetDriveTypeW` on the UI STA. It runs once per navigation
  generation whenever a sort read is unsorted, unavailable or recovered. This is real
  Shell work done only for a log line, whatever `g_perf` says.
- Several `Wh_Log` lines are not gated on `g_perf`, and most include folder paths:
  `[GPU sort] REQUEST_DEFERRED/UNSORTED` (`13090`), `READ_FAILED`, `READ_UNSORTED`,
  `READ_RECOVERED`, `VIEW_STATE`, `[GPU device] CREATE` (`18515`) and `RELEASE`
  (`18269`), `[GPU presenter] AWAIT_NAMES/AWAIT_END` (`33990`),
  `[GPU navigation] DOUBLE_CLICK_UP(_IGNORED)` (`37611`), and multiple-rename failures.
- The option's description says logs include paths only when it is enabled. These
  lines bypass that, and the mod's own comment notes that Windhawk's
  OutputDebugString transport can block.
- Fix: gate all of these on `g_perf`/`g_pipelineTracing`, and run the probe only when
  logging is on.

### H4. A modal `MessageBoxW` runs inside rename and window-procedure paths
`ReportMultipleRenameFailure` (`latest.cpp:28671`) is reached from `FinishRename` →
`RenameSelectionNatively`, and from the `kMsgNativeRenameStep` handler (`37462`).
- The message box runs a nested message loop while callers hold `ViewState&`. A tab
  close, navigation, Shell notification or settings message can be processed inside it.
  `OverlayProc`'s `WM_LBUTTONDOWN` path calls `FinishRename` a second time
  (`latest.cpp:37025`) and then uses `s` without re-checking `State(hwnd)`.
- The text is hard-coded English, and it duplicates DefView's own error UI. DefView
  already shows rejection messages for invalid names.
- Fix: do not block. Post a message, or rely on DefView's UI, and log. If a prompt is
  kept, show it from a posted message after the transaction has unwound, and re-validate
  `State(hwnd)` afterwards.

## Medium

### M1. Shell icon invalidation now re-queries every visible property column
`InvalidateShellIcons` (`latest.cpp:32990`) now also runs `InvalidateDetailJobs` and
`++propertyEpoch`. Every `SHCNE_UPDATEIMAGE` or association change therefore refetches
all Details, Tile and Content properties for all visible rows. OneDrive and other sync
providers broadcast image updates often. Only status-glyph cells depend on icons;
invalidate those keys (or the status-icon cache epoch) instead of all properties.
`WM_DPICHANGED` doing the same is reasonable, since glyph size depends on DPI.

### M2. Activity in any subfolder refreshes the containing row, and can trigger folder-size recomputation
`latest.cpp:35680`. The watch is registered recursively (`SHChangeNotifyEntry{pidl, TRUE}`,
`latest.cpp:11796`). Every create, delete or update anywhere below a listed folder
queues an update for its top-level row. With a folder-size provider (Better file sizes),
that row's refresh recomputes a recursive size. A build or `npm install` under a listed
folder produces a steady stream of these. `QueueShellItemUpdate` coalesces them, but each
flush still repeats provider work. Consider batching per row and per frame, or refreshing
folder size only for Size sorts and grouping or when the Size column is visible.

### M3. `ResolveFolderContentSizes`: cancellation is too coarse and the lock is too strong
`latest.cpp:10314`.
- `Fresh` checks `DirectoryJobCurrent` only every 32 entries (`10336`). Each
  `GetDetailsEx(PKEY_Size)` on a folder can be a full recursive scan, so after the user
  leaves, the lane can keep working through up to 32 slow scans. Check before every
  folder.
- `Recorded` holds `directoryLock` exclusively (`10323`) while it walks every entry and
  allocates `parentOf()` strings. It only reads, so use a shared lock and compute the
  parent once.
- The `folderSizeCheck` follow-up job (names lane → layout lane) recomputes all folder
  sizes Fresh on every size-sorted navigation. If a provider returns values in stages
  ("calculating", then a number), each stage triggers another refresh.

### M4. In-place folder replacement skips the navigation reset
`ReplacesFolderInPlace` (`latest.cpp:40026`) and the new `else if` branch in AttachView
update `folderPath`, `folder` and identity, then requery. They skip
`ResetMouseGestureForNavigation`, `CancelRename`, `CancelClickRename`,
`nativeRenameHold`/`nativeRenameText` cleanup and the `mouseFolderEpoch` bump that a
normal navigation performs. An open rename field, armed slow-click, held multi-rename
selection, marquee or drag can carry over to rows of the new search result. Most
consumers re-check the path, but rename hold and marquee state are keyed by token, not
path.

### M5. Hooking GetDC/ReleaseDC for the rename field breaks IME composition and affects the whole thread
`latest.cpp:1417`, `27823ff`.
- While the rename field is up, any `GetDC(editHwnd)` on that thread gets an offscreen
  1×1 memory DC. The EDIT draws IME composition (underline and clause attributes)
  through GetDC. `PaintRenameText` draws only text and selection, so CJK and other IME
  users lose composition feedback in the field.
- `RenameEditProc` force-repaints synchronously (`RedrawWindow … RDW_UPDATENOW`) after
  every char, key, mouse-move-with-capture and capture timer, and runs
  `RenameCaretToDisplay` after every message.
- `RenameCaretToDisplay` skips remapping when the GDI caret equals the last displayed
  position. If the EDIT's own caret position happens to equal that value for a different
  index, the remap is wrongly skipped.
- Recommendation: when an IME composition is active (`WM_IME_STARTCOMPOSITION` to
  `WM_IME_ENDCOMPOSITION`), turn the sink off and let GDI text show.

### M6. The rename underlay writes stale pixels into Explorer's frame outside WM_PAINT
`CaptureRenameUnderlay`/`RestoreRenameUnderlay` (`latest.cpp:27536`, `27566`) snapshot
the frame DC and later BitBlt that snapshot back onto Explorer's frame surface. The
only validity check is the frame client size. Anything that repainted underneath in the
meantime (hover in the details pane or status bar, theme or accent change, another
child's content) is overwritten with old pixels until those owners repaint. A
`RedrawWindow` follows, so it is mostly a one-frame artefact, but it is a fragile
workaround. Prefer invalidating the vacated rectangle with `RDW_UPDATENOW` on the
siblings that own it, or keep the field inside a surface the mod owns.

### M7. New-menu hook: vtable discovery and missing thread check
`NewMenuInvokeCommandAddress` / `ObserveNewItemCommand` (`latest.cpp:40755`).
- The hook target is found by creating `CLSID_NewMenu` on the init thread and reading
  vtable slot 4. If that thread were already MTA, `CoCreateInstance` would return a
  proxy, or fail because `IContextMenu` is not remotable. The hook is then silently
  missing, or attached to proxy code. Hooking the vtable of the object you are given is
  safer, or at least check that the address lies inside `shell32.dll`.
- `ObserveNewItemCommand` finds a `ViewState` and calls `ArmInteractiveCreation`, which
  mutates owner-thread state, without checking
  `GetWindowThreadProcessId(state->hwnd) == GetCurrentThreadId()`. Shell can invoke
  context-menu commands off the view thread (async invoke). **Verify**, and add the
  check either way.

### M8. Multi-item rename depends on DefView's internal queue order
`kMsgNativeRenameStep` (`latest.cpp:1211`, `37462`) assumes a message posted after
`DoRename()` is processed after DefView has created its editor, and that the step-1 post
lands after DefView's commit has read the selection. That ordering is not a documented
contract (an entangled-queue assumption per AGENTS.md). If DefView defers editor
creation (a timer, or an animation in grouped views), step 0 escapes the editor and
shows the failure box (H4). Nothing releases the hold (`nativeRenameHold`) except steps,
navigation and failures, so a lost step leaves GPU→native selection sync suppressed for
that token. Prefer detecting DefView's editor through its own notification (the existing
`AdoptNativeRenameEditor` focus path), with the posted step only as a fallback.

### M9. Per-frame allocations in Paint
- Zebra bands (`latest.cpp:23844ff`): every paint builds `next` (a vector of structs that
  each copy a `std::wstring` section key), two `std::map<pair<wstring,int>,…>`, a
  `std::map<wstring,…>` of bodies, and a `fills` vector. The snapshot is rebuilt whenever
  `scrollNow` changes, which is every scroll frame. The old code was allocation-light.
  Use section indices instead of string keys and reuse member vectors.
- `DrawSelectionCheckbox` without a theme sets `state.checkboxResources = {}` for every
  checkbox drawn (`21875`): six `ComPtr` gradients plus six ramp arrays reset per box per
  frame. `PaintGroupBadge` (`21571`) and `DrawSwipeIndicator` do the same. Reset only
  when the snapshot changes.
- `SearchHighlightRanges` runs `FindNLSStringEx` for every visible name on every frame
  in search folders. Cache the ranges per entry and term set.
- The Content view builds a `label + L": " + value` string per row per frame.
- `PRESENTATION_MODEL_FIELDS` now copies `searchHighlightTerms` (a vector of wstrings)
  on every presentation submission.

### M10. Icon queue insertion is O(n²) — withdrawn (1.0.14)
**Correction:** each lane's queue is capped at `kMaxIconJobs` (128), so an
enqueue scans and inserts into at most 128 jobs. The quadratic growth over
thousands of jobs described below cannot occur; no change was made.

`latest.cpp:8610`. Each enqueue does a linear `find_if` and a mid-`deque` insert. A large
folder's first pass enqueues thousands of jobs, so the cost is quadratic. Use per-priority
buckets, or append and sort once per batch (the reprioritizing pass already
`stable_sort`s).

## Low and code quality

- **L1. Left/Right arrows now move the selection in List and Details**
  (`IsKeyboardMovementKey`, `latest.cpp:26459`). Native Details does not do this.
  Removing `HandleGroupKeyboardDirection` also means Left/Right no longer collapse or
  expand a group from an item. The `grid` parameter is now unused. Confirm this is
  intended.
- **L2. `SelectionFeedbackVisible` (`9060`)** returns true whenever a rename editor
  exists, even after Explorer loses foreground. Restrict it to the creation-focus window
  it is meant for.
- **L3. Undocumented internals:** uxtheme ordinal 133 (`AllowDarkModeForWindow`), the
  hard-coded uxtheme property atoms 43280, 43281 and 43294 (`7701`), and
  `Explorer::CommandModule` part 4. `WindowThemeName` uses `GetAtomNameW` (the local
  atom table); **verify** that uxtheme stores these names there rather than in the global
  table. Failures fall back to defaults, so the impact is cosmetic.
- **L4. `DriveTiles` now requires `FVM_TILE`** (`5472`). This PC in Large/Medium icons
  loses its drive usage bars. Behaviour change; confirm.
- **L5. Theme parser:**
  - `Recover` (`605`) calls `Parser{}.ParseXml` once per attribute. Each call loads and
    frees `xmllite.dll` and creates a new reader, up to 2048 times per settings change.
    Reuse one runtime and reader.
  - `<stop>` outside `<scale>` silently becomes an element named "stop".
  - In `ReadPaint`, `comma != token.npos` compares the wrong variable. It works only
    because both are `npos`.
  - `Theme::settingsMutex` is redundant with `LoadSettings`'s lock.
- **L6. `AssignExtraShellSortValue` (`9363`):** converting `VT_DATE` to `SYSTEMTIME`
  drops sub-second precision, so Shell-column date sorts tie where native does not.
  **Verify** that column (`VT_DATE`) and property-store (`VT_FILETIME`) values use the
  same time base (UTC vs local). One sort can mix both through the fallback paths.
- **L7. `AdoptPreviousNamespaceIdentities` (`10860`):** nothing stops two new rows from
  adopting the same previous identity, which would create duplicate path keys. Track
  which previous entries are already used.
- **L8. Status glyph caches:** `DecodeStatusIcons` and `StatusIconBitmap` flush the whole
  cache when they hit 64 entries instead of evicting LRU. `EntryPayloadBytes`
  double-counts shared glyph buffers (the comment acknowledges this), which evicts
  folder-cache entries early.
- **L9. `ResolveShellFileLabel` (`9298`):** an extension whose display name is neither
  the stem nor the full name is never memoized, so it costs one `SHGetFileInfoW` per
  file on every enumeration.
- **L10. `UpdateSearchHighlightTerms` (`9220`)** calls `SHGetNameFromIDList(SIGDN_DESKTOPABSOLUTEEDITING)`
  on the UI thread for every new folder identity, not only search folders. `+` in the
  query is not decoded as a space.
- **L11. `ReleaseViewToggle`** deletes `viewToggleTipFont` even when the tooltip window
  was not destroyed (owner-property mismatch). That tooltip then holds a deleted HFONT.
- **L12. `StyleViewToggle` (`41873`)** runs `EnumThreadWindows` plus
  `TTM_ENUMTOOLSW` on every `RefreshViewToggleForFrame`, before its own early-out.
  Status-bar location events call this often.
- **L13. `kAnimationDurationScale` leaks into physics.** It now scales touch velocity
  (`TouchElapsedMs`, `34638`) and swipe springs, not only animation durations. A debug
  build at 2.0 would also change gesture feel.
- **L14. `ReconcileCompactRows`** reads the registry on every visibility reconcile and
  settings broadcast. It is event-driven, so the cost is small, but it could filter on
  the `WM_SETTINGCHANGE` "Policy"/"ShellState" hint.
- **L15. Pre-sort removed.** Names now always wait for the Shell sort read unless
  `sortReadUnavailableToken` is set. Users who disabled pre-sort for faster first paint
  have no way back. Mention this in the CHANGELOG.

## Process notes
- This "patch" step (1.0.4 → 1.0.10) adds about 4.9k net lines to one 41k-line file,
  including a full XML/CSS-like theme engine. Moving the theme parser, rename text
  renderer and status-glyph pipeline into separately testable units would make reviews
  like this cheaper.
- Several fixes in this diff are diagnostics rather than fixes (H3). Before release,
  either gate them or turn the underlying logs into regression tests.

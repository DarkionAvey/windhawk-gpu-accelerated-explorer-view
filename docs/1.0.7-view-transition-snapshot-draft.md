# View-transition snapshot draft

Status: implemented as an unpublished draft in the existing 1.0.7.cpp at the user's request. No tests added or run; no production build performed. latest.cpp remains published 1.0.6.

The draft uses applied mode/icon size for geometry, captures before destination adoption, preserves shaped snapshots through grid-mode changes and interruptions, and retains zoom snapshots through resize/pinch handoff. x64 and ARM64 syntax checks passed with the existing unused PageLength warning. These checks do not link the DLL or verify live Explorer animation. The proposed checks below remain future work; optional detail/selection crossfades and a unified sampling-clock refactor were not added.

## Tiles failure

In 1.0.7.cpp, ApplyViewLayout assigns cachedNativeMode to the requested destination before CapturePresentedGridCells(state, true). RefreshNativeViewMode and the native command observation path can also update that field before ApplyViewLayout runs.

TileLayout and the Small Icons branches in LayoutItem read cachedNativeMode, while gridView, itemWidth and row metrics still describe the outgoing layout. Leaving Tiles for Content or Details therefore captures a hybrid: old grid cells, but the centered icon geometry of an ordinary icon grid. LayoutRowVisual then faithfully animates from that incorrect oldIcon rectangle. A wide tile makes this look like an arrival from the right.

The reverse direction does not have the same error: the outgoing list branch does not use TileLayout to place its icon. This explains the asymmetry in the report at source level; live Explorer reproduction has not been performed.

## Proposed changes

1. Separate observation from applied layout consistently. Use layoutNativeMode for geometry and applied visual policy: Tiles/Content classification, Small Icons packing and metrics, item/checkbox geometry, and thumbnail policy. Keep cachedNativeMode for Shell observations and mode adoption. Moving one assignment is insufficient because callers can already have observed the destination.

2. Capture before changing any applied layout fields. Make the outgoing capture an explicit part of the shared layout transaction, before mode, icon size, packing or metrics change. Pass that capture into the existing zoom/reflow path rather than having BeginAnimatedZoom discover its source after ApplyViewLayout has changed layoutNativeMode. Preserve existing immediate destination hit testing and bounded visible-row sampling.

3. Retain component geometry for layout changes within grids as well as list/grid changes. Currently only the latter requests icon/name rectangles; grid-to-grid mode changes capture cell bounds without shapes. Tiles, Small Icons and centered icon grids arrange the icon/name differently inside those cells. Reuse the existing shaped RowMotion path for those mode changes, with the same clock as packing and metric interpolation. Ordinary same-mode zoom/resize should retain their existing behavior unless they interrupt an active shaped morph.

4. Preserve an active morph when another input retargets it. CapturePresentedGridCells defaults to shapes=false for zoom, pinch and resize. Even if LayoutRowVisual describes a partly completed icon/name morph, those callers discard the component rectangles. Preserve current component geometry whenever the outgoing transition is shaped, regardless of which input caused the retarget. Sample related row/header/zoom geometry at a consistent transition instant; do not restart from a settled endpoint or add timer delays.

5. Settle or retarget the previous zoom deliberately at a list/grid boundary. StartGroupingTransition rejects reflow while zoomAnimating is true, and AdvanceRowHeight(state, true) can settle old metrics after capture. Resolve this ordering in the shared transaction so the outgoing pose is sampled first and the previous zoom cannot suppress the replacement morph. Header/column changes must still finish their setup before installing row motion, since SetColumnViewMode stops row transitions.

## Scope and constraints

Keep existing tab-owned state, owner STA handling, native suppression, provider lanes and immediate destination interaction. No new options, provider calls, guessed dimensions or timer intervals are needed. Use the existing logical coordinate system and RTL mirroring; account for scroll translation exactly once.

PrepareRowComposition already excludes live reflow and zoom transitions. There is no evidence that a separate compositor animation implementation is needed for this fix. Review its handoff when a morph finishes or is replaced by an ordinary row diff, but keep changes tied to an established loss of geometry.

The current shaped snapshot contains icon/name bounds only. Tile detail lines, Content aside lines, drive bars, checkbox and selection geometry use destination-specific paths. Review these for visible discontinuities alongside the primary fix; do not claim a full old-view pixel snapshot or promise crossfades without confirming their rendering behavior.

## Verification to design after draft review

Use private fixtures and real Windows view-mode APIs. Cover both directions between Tiles and Content/Details/List, plus Tiles/Small Icons/centered grids; include items in multiple grid columns. Independently verify that the first animated icon/name rectangles match the outgoing rendered geometry, then reach the destination without a positional jump.

Exercise interruption by another view command, Ctrl+wheel, pinch/resize, scrolling and directory diffs. Include RTL, DPI, horizontal Details scrolling, selection/checkbox state, grouped headings, reduced/disabled animation and tab/navigation boundaries. Split tests along natural dimensions to stay within the fixed 120-second limit, run each new test alone and with the suite at Jobs 16. Offscreen checks do not establish live Explorer smoothness.

No tests were written. No production build or publication is planned under the current request.

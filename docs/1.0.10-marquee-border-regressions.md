# Marquee and shared border checks

`theme-marquee` draws the production marquee on a private GPU target. It checks inside-border placement and whole-pixel widths at 96, 144 and 192 DPI, including physical pointer coordinates in RTL. It also checks solid, dashed, dotted and disabled borders on rectangles and a collapsed vertical line; transparent border-only drawing; rounded corners; light/dark overrides; invalid-value inheritance; color alpha multiplied by marquee opacity and fade; gradient interpolation; cache invalidation and release; and routing back to native drawing when the theme is cleared or high contrast is enabled.

The existing highlight, tooltip and scrollbar tests now inspect visible border patterns at the same DPI values. A solid border must have no gaps, dashed and dotted borders must contain ink and gaps, dots must have shorter visible runs than dashes, and `none` must leave the sampled edge empty. Pixel colors must retain correct red premultiplication. Warm rendering must be stable. Scrollbar checks cover both axes and every interaction state in LTR and RTL. Border customization must not change tooltip layout, and device teardown must release cached stroke styles.

The gradient expectations use independent interpolation; border-width expectations use independent DPI arithmetic. These checks do not call the mod's stroke helpers to derive their expected pattern. No keyboard input, focus, clipboard or user folders are used. These are offscreen component checks, not live Explorer presentation measurements. The existing `marquee-selection` check separately exercises selection behavior.

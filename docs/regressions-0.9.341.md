# Serial regression investigation for 0.9.341

The tested source is the user's hardware-verified candidate, unchanged during
this investigation. SHA-256:
`C66DB23293DC7EF7690A482469C7612D21CEE27F48366EEBAD5C3A8E5006F151`.
The published source remains 0.9.340 pending the release step.

## Findings and changes

- The old `-Jobs 1` branch ran every suite inside one process and fixture.
  Full runs now use the same manifest and per-suite processes at every job
  count. At `-Jobs 1`, compilation and execution remain sequential. This also
  prevents fixture artifacts and mod globals from leaking between suites;
  for example, the touch suite writes a preview BMP while the Shell snapshot
  suite expects the original 512-file fixture. This is a harness dependency,
  not a requirement to change the PC's state.
- The touch fixture expected a drag at exactly `SM_CYDRAG` and immediate OLE
  entry after its promotion stub returned. Those expectations described the
  removed workaround. Contacts now move within the actual viewport until
  Windows recognizes manipulation. The assertions require one native promotion,
  no OLE without native mouse delivery, and safe release/cancellation. No mouse
  messages are fabricated to make an end-to-end drag appear to pass.
- The drag text test sampled the old badge dimensions and palette. It now
  samples the configured count scale and supplies an explicit neutral palette
  for antialiasing comparisons. The direct emoji reference also matches the
  recorded path's wrapping and rendering parameters. The common visible-width,
  centering, actual popup-boundary and original prohibition-artwork assertions
  remain in place. The initial width failure is not classified as a defective
  machine or used to exclude font customizers from the gate.
- Native rename color failures recorded zero color callbacks and zero
  `WM_PAINT` deliveries, despite a visible, nonempty, live editor. A successful
  `RedrawWindow` return was insufficient evidence that its client had painted.
  The probe now invalidates the actual client, checks its update region, and
  calls `UpdateWindow`. A native paint observer verifies delivery before the
  existing text/background/brush and buffered-copy assertions. There is one
  invalidation, no assertion retry, and no manufactured paint message.
  `PrintWindow` was checked and is unsupported for these offscreen EDITs;
  it is not part of the final probe.
- Touch calibration now reports the failing Windows API, error and device
  counts, and rejects empty digitizer/display bounds before input is fed.
  The DLL lifecycle probe checks this prerequisite before creating its live
  presentation/touch state. Graphics availability now fails explicitly with
  HRESULT/stage diagnostics instead of silently skipping the suite.
- Native-key deferral now uses the existing private modifier/focus fixtures.
  It asserts a valid interactive fixture and accepted routing rather than
  retrying against live input state three times and then skipping the check.

These are native API/component and DLL-lifetime checks, not measurements of
displayed frame rates. The actual touch-to-OLE queue handoff still requires
hardware; the user confirmed it separately, including This PC.

## Final verification — 2026-11-02

The complete optimized gate passed in 295.43 seconds. All five build tasks and
all 12 regression tasks ran with a maximum of one process. The 11 pipeline
groups and DLL-unload group all returned zero, with no skipped checks or failed
prerequisites. Both regular and minified sources linked against the installed
Windhawk host; minification fixtures passed. Critical compiled callback stack
frames stayed within the 8 KiB limit (maximum 2,264 bytes).

Repository orchestration checks also passed after the harness changes. The
final run used the existing PC configuration; its foundation suite reported
active MacType and verified consistent direct/cached text policies. No font
customizer exclusion or machine-wide setting change was needed.

The command was `tests/run-regressions.ps1 -SourceFile 0.9.341.cpp
-MinifiedSourceFile tests/.build/0.9.341-regression-minified.cpp -Jobs 1
-KeepArtifacts`. The minified input was generated by the repository's
`ConvertTo-MinifiedMod` function. Logs are retained in
`tests/regression-341-serial-verified.log` and
`tests/repository-341-serial-verified.log`; per-task logs/CSVs and binaries remain
in the artifact directory printed by the runner.

The source hash still matches the hardware-approved candidate. No release was
published or archived during this nonpublishing test run.

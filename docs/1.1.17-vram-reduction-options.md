# VRAM reduction options (to benchmark)

Context: 1.1.17 removed resize flicker by never replacing a visible tab's swap
chain for a smaller viewport. Lane buffers are created and grown to the frame's
client area (`ExtendToFrameReach`), grow to the monitor work area only during
frame edge drags, and are trimmed back to the frame reach only while the
overlay is hidden (`AdvanceStandbyGraphics`). Swap chains already use the
minimum of two buffers (`kPresentationBuffers`).

Each option below must be benchmarked before adoption: GPU memory per tab
(`[GPU memory]` log, DXGI budget), number of chain rebuilds per scenario, and
whether any rebuild lands on screen. Scenarios: new tab, preview pane toggles,
splitter drag, frame edge drag, maximize/restore, tab switching with 1/5/10
tabs, monitor change.

1. **Release background tabs' swap chains.** Largest saving (every hidden tab
   holds a full chain, roughly 26 MB at 2476x1327). Rebuild while the tab is
   shown again; the content change of a tab switch hides the rebuild. Risk: the
   switch-back path presents the retained image immediately
   (`PresentCachedTabSurface`); the first frame must arrive without a gap.
   Measure: total chain bytes vs tab count, switch-back time to first frame.

2. **Exact height, frame-reach width.** Explorer's panes and splitters only
   change the list width; height changes come from frame sizing/maximize,
   which already use their own path. Saves ribbon/address/status rows (about
   15% per tab on a 1327 of 1565 layout). Measure: bytes per tab, rebuilds
   during pane toggles (must stay zero).

3. **Width capped at frame minus navigation pane.** Saves the navigation pane
   width (typically 300-400 px) but hiding the navigation pane would rebuild
   once on screen. Lowest priority; only if 1 and 2 are insufficient.

4. **Trim work-area buffers after an edge drag at the next content change.**
   A visible tab keeps work-area buffers after WM_EXITSIZEMOVE until it goes
   off screen. Trim at the next navigation, view-mode switch or zoom, where the
   content change hides the rebuild (event driven, no timer). Measure: bytes
   held after a drag, rebuild visibility.

5. **Shared D2D device across tabs.** Each tab device has its own internal
   cache (capped at 16 MB). Large refactor; measure first.

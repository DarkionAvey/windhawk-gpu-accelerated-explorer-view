# Rename shortcut input isolation

The reported `rename-editing-shortcuts` failure showed Ctrl+Left moving from position 22 to 21 instead of 17: Windows handled Left without Ctrl.

The test set its thread-local keyboard snapshot before retrieving a posted key message. Windows message retrieval can refresh that snapshot from the input queue. User keyboard activity can therefore affect the test even though it never injects input into the desktop.

The test now applies its keyboard snapshot after message retrieval, immediately before native translation and dispatch. The existing scoped modifier fixture keeps the mod's own modifier reads independent of nested Shell message pumps. All word movement, selection, deletion and undo assertions remain intact. Native EDIT handling and Windows character translation still perform the editing; the test does not synthesize character messages or change production code.

The user's diagnostic failure is retained in `gpu-mod-diagnostic-05b7059cfef74037b26ff49652a0f3a0/results`. Focused validation artifacts are in `tests/.build/rename-shortcuts-fix-20261113-01`.

Validation passed: ARM64 and x64 builds, followed by the individual `rename-editing-shortcuts` test (0.52 seconds). Ctrl+Left reached position 17, and all subsequent selection, navigation, deletion and undo checks passed. No full suite or publication build ran.

# Chevron tip overlap on translucent chevrons (open, deferred from 1.1.22)

User report: the expand chevrons of hidden (dimmed) items show a brighter
spot at the tip.

## Cause

`StrokeChevron` draws two lines and a disc at the tip. With a translucent
brush the tip pixels are covered two or three times, so they are brighter.

## Attempted fix and why it was reverted

Drawing one open path geometry with a round join (as the swipe arrow does)
removes the overlap. It broke `graphics-isolation` (header slide/fade):

```
settled/animated alpha around the header sort chevron, visibility 0.5625
row 9:  22/9   203/99  203/108  22/9
row 10: 22/9   203/99  255/143  255/143 203/117  22/9
```

- Fully covered pixels fade exactly (255 -> 143).
- Edge pixels with the same settled coverage (203) fade unevenly (99 left,
  117 right; linear would be 114). The test allows 8.
- Snapping the tip once and placing the wings at whole-pixel offsets
  (a rigid shape) changed no pixel, so per-point rounding is not the cause.
- So the faded header chevron is rasterized differently from the settled
  one, not merely moved. The old overlap saturated these edge pixels and
  hid it (the test's comment names that overlap).

## Next steps

1. Find how the animated header (column mode transition, plane=0 fallback,
   `ColumnHeaderOffset`/`ColumnHeaderPaintHeight`) draws the chevron versus
   the settled header: transform, layer, antialias mode, brush opacity.
2. Fix that path, then reapply the single-geometry chevron. The test is not
   to be relaxed.
3. The pixel dump added to `tests/animation-smoke.h` prints the
   neighborhood on failure.

# Sticky group collapse draft

The existing toggle shrank the group while retaining the viewport's offset into its body. Document-wide scroll clamping did not prevent that offset from passing the next heading, including an already collapsed next group.

The 1.0.7 draft retargets the existing scroll animation when collapsing the group containing the viewport and its natural heading has scrolled above the viewport. The destination is that group's document top, keeping its own collapsed heading visible so the user can identify the group. It does not search for an expanded group or selected item. Document-end clamping still applies when too little content remains to put a heading at the top.

The common toggle covers pointer, touch and keyboard paths. Expanding groups and toggling headings that have not become sticky keep their existing scrolling behavior. Selection remains unchanged. This uses existing scroll and collapse animations, without new timers, state or renderer-specific handling.

x64 and ARM64 syntax checks passed. No regression tests or production build were run. Live checks still needed: collapse midway through a long group with its next group expanded and collapsed; repeat near document end and in grid/Content layouts; interrupt the scroll/collapse with input and reverse the toggle.

# Cloud status property merge

The submitted source was based on 1.0.6. Its status changes were merged into
the existing 1.0.7 draft, preserving unrelated draft work.

Microsoft documents the [serialized property-store format](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-propstore/1eb58eb3-e7d8-4a09-ac0e-8bcb14b6fa0e)
and the system [memory-store deserializer](https://learn.microsoft.com/en-us/windows/win32/api/propsys/nf-propsys-ipersistserializedpropstorage-setpropertystorage).
The implementation uses Windows to read the format rather than reproducing its
binary parser. It accepts both blobs and byte vectors, including nested custom
states, but only treats stores carrying the StatusIcons property list as status
containers. Other binary properties keep their ordinary Shell formatting.

The cloud provider [item-property contract](https://learn.microsoft.com/en-us/uwp/api/windows.storage.provider.storageprovideritemproperty?view=winrt-26100)
defines a provider's state label, ID and icon resource. Microsoft's
[CloudMirror sample](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/CloudMirror/CloudMirror/CustomStateProvider.cpp)
demonstrates custom states with a Shell resource reference. These are not
OneDrive-specific. The precise internal nesting of System.StorageProviderUIStatus
is not fully specified by those public contracts; support is conditional on
recognizing its property list and expected types. Proprietary formats and
non-resource image references are not assumed to work.

Enumerated states obtain their icons through the documented
[IPropertyEnumType2::GetImageReference](https://learn.microsoft.com/en-us/windows/win32/api/propsys/nf-propsys-ipropertyenumtype2-getimagereference).
The same path handles scalar columns with schema image references. Labels stay
available for tooltips and as fallback if an icon row cannot be decoded or
uploaded completely. No provider name, state number or icon resource ID is
hardcoded in the mod.

Review corrections beyond the submission:

- Bound serialized input, list/vector counts, string lengths, decoded dimensions
  and cache retention; check variant types, pointers and HRESULTs before use.
- Keep CPU caches on each existing detail lane, without a cross-tab cache lock.
  Cache keys retain separate locations, avoiding delimiter collisions.
- Treat missing icons as an incomplete row instead of silently hiding a state.
- Include icons in cell comparison, asynchronous result merging, cached row
  comparison and memory accounting. The submitted text-only merge would retain
  obsolete icons when a status changed.
- Paint icon-only cells, retain text on upload failure, and use whole glyphs
  for overflow, fitting and clipping checks. Preserve RTL and transition opacity.
- Bound decoded output to the requested small-icon size and draw within exact
  cell geometry, including fractional animation bounds. Oversized resources
  cannot expand a cell; icons without enough horizontal room are omitted whole.
- Scale cached glyphs immediately with current Windows small-icon metrics;
  invalidate detail generations on DPI changes to obtain sharp replacements.
- Release status textures with their device and invalidate worker cache entries
  when Shell images or associations change. Refresh status cells through the
  same existing detail lanes, and check cancellation between icon extractions.

Regression fixtures use Windows' serializer and registered schema, with private
files/windows and offscreen GPU readback, including a Windows-created 512-pixel
icon in a short row. They do not establish live Explorer
frame rates or certify every installed cloud provider. Actual provider behavior
still needs a live Explorer check.

Validation: both status regressions passed in separate processes, including the
oversized-icon extension. ARM64/x64 regular and minified compilation passed in
the release gate. The full 16-job gate stopped at `paste-focus` with "native
Paste menu resolution invoked a departed folder's command"; later entries were
cancelled or not started. A diagnostic run with unchanged assertions passed,
which does not resolve that earlier failure. Publication remains blocked and
the published 1.0.6 source is unchanged. Paste diagnostics now distinguish an
unhandled shortcut from an actual stale command invocation.

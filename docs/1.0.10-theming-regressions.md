# Theming regression coverage

The named regressions below are opt-in individually and also registered for the
normal release gate. Each has its own process and declares `PARALLEL`. None
uses user folders, changes the clipboard/focus, or changes system settings.

| Test | Coverage |
|---|---|
| `theme-parser-xml` | Native XmlLite entities/Unicode, generic dictionaries, supported scopes, fragment handling, invalid input and security/resource limits |
| `theme-parser-values` | Independent CSS color values, gradient directions/stops, shorthand colors, inheritance, light/dark overrides, invalid-value fallback and shadow limits |
| `theme-parser-settings` | Windhawk string ownership, settings read count, theme-only change detection, last-valid retention, partial recovery, clear and retained snapshot lifetime |
| `theme-parser-recovery` | Repeated element/mode blocks, duplicate attributes, last complete value, intact fields before/after malformed attributes, missing quotes/closures and safe recovery limits |
| `theme-highlight-base` | Shared `FillSelectionRect` style across all three rendered states |
| `theme-selection` | Selected background and theme option effect coverage |
| `theme-hover` | Hover background |
| `theme-selected-hover` | Selected-and-hovered background |
| `theme-tooltip` | Layered tooltip fill, border, corners, hard/soft/colored shadows, shadow cache, text palette, transparency, appearance and DPI |
| `theme-tooltip-antialiasing` | User/Windows antialiasing policy, solid and gradient opacity, rounded-edge safety and grayscale pixels without RGB fringes |

Each highlight test reads actual Direct2D pixels at 96, 144 and 192 DPI in LTR
and RTL. Border widths use independent rounding/DPI arithmetic. Gradient colors
use independent interpolation averaged over noise rows. Alpha uses independent
color-alpha × element-opacity arithmetic. Clearing and high contrast must
restore the legacy pixels, and cached texture bytes must stay within the
documented bound. These are offscreen component checks, not live Explorer
presentation or performance measurements.

The theme option has an `OptionCatalog` entry, an `OptionEffects::kCoverage`
entry, and valid/invalid/reset XML values for the existing live option sweep.
The sweep is not needed to run a single theme regression.

Run an individual test without publication:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run-regressions.ps1 -SourceFile 1.0.10.cpp -Tests theme-parser-recovery -Jobs 1
```

The runner retains failures, stops at the first failure, rejects injected or
restricted test processes and enforces the fixed 120-second per-test limit.
It does not disable Windhawk or change its exclusions. No full suite or
publication is part of this development check.

## Validation on November 13, 2026

All 10 new theming regressions passed individually. The four existing checks
`user-options`, `option-coverage`, `item-tip-typography` and `item-tip-shadow`
also passed individually. The final recovery scope-isolation change and texture
teardown assertions were followed by successful individual runs of all eight
affected parser/highlight checks. No full suite, parallel suite or publication
was run, as requested.

The working mod compiled and linked for ARM64 and x64 against the installed
Windhawk host libraries. ARM64 was not executed. The callback stack check passed
with a maximum of 2,312 bytes. Detailed local logs are retained under
`tests/.build/theme-individual-20261113-02/` and
`tests/.build/theme-individual-20261113-03/`.

The first value test exposed incorrect `#RGB` expansion. The implementation was
corrected, and its independent color expectation was retained. Recovery also
isolates unnamed damaged elements so their appearance blocks cannot affect the
preceding element. The earlier failing result is preserved under
`tests/.build/theme-individual-20261113-01/`; it was not hidden or retried without
an implementation correction.

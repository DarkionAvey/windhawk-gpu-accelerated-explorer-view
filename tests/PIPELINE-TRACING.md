# Capturing a pacing or motion problem

Use **latest.cpp**. Enable **Detailed pipeline tracing (high volume)** and
**Frame time logging** in Windhawk. They are independent of Performance logging.
Detailed tracing defaults off and allocates no buffer or writer until enabled.

Version 0.9.195 adds `selection.capture[batch,total,complete,ms]`,
`selection.resolve`, `selection.import.ready`, `selection.capture.retry` and
`selection.import.retry`. Generation IDs join owner-thread PIDL capture to the
existing selection worker and UI publication. Clipboard batches record
`clipboard.capture[batch,total,ms]`. See [count-limit findings](LIMIT-AUDIT-0.9.195.md)
for the Delete/Undo evidence and the remaining native-dispatch boundary.

Open a fresh Recycle Bin tab, drag the scrollbar through the directory, then
repeat after the data is warm. A few seconds of each is sufficient. Disable
detailed tracing afterwards so the writer can drain the remaining records.
Keep the full capture, including `[GPU pipe] START`, `[GPU pipe] DROP`,
`[GPU frames]` and `[GPU stall]` lines. Disabling/re-enabling reuses the same
tab's writer; closing the tab or unloading joins it through the normal regulator.

Each tab has its own 8,192-record buffer and background writer. Producers use a
nonblocking try-lock. Full/contended buffers count lost records instead of
waiting on the UI thread. `DROP` reports these losses and `STOP` includes their
cumulative count. Missing span endpoints near DROP/disable/unload are not proof
that an operation hung. Output volume and the external log viewer can still
affect a profiling session; compare cold and warm motion under the same settings.

For navigation appearance or opacity problems, the separate **UI transition diagnostics** option records focused `ui.*` events without requiring the full pipeline trace. See [UI capture instructions](UI-TRANSITION-DIAGNOSTICS.md). Both options reuse the same tab-owned buffer and writer.

## Record schema

`START` declares `schema=1`, the GPU HWND, QPC frequency, buffer size, writer
thread and installed mod version. Ordinary records contain:

| Field | Meaning |
| --- | --- |
| `gpu` | Owning overlay HWND; buffers and writers are independent per tab. |
| `n` | Accepted record sequence within that buffer. |
| `qpc` | Event timestamp, captured on the producing thread. Divide differences by `qpcHz` for seconds. |
| `tid` | Producing thread, rather than the writer. |
| `f`, `i` | Current frame and processed-input counters. Worker events observe the current frame; their job tokens/request IDs establish causality. |
| `span` | Unique begin/end pair, including nested operations. |
| `phase` | `B` begin, `E` end, `P` point event. An `E` record's first numeric value is elapsed milliseconds. |
| `a`, `b` | Operation-specific integer IDs/flags, printed in hexadecimal. |
| `v` | Four numeric values. Point-event names list their meanings in brackets. Scope endpoints use the first value for elapsed time. |
| `note` | Folder context for navigation records. No per-frame folder-string formatting is required. |

The normal Windhawk timestamp is **write time**. Use QPC event timestamps to
align asynchronous events across tabs/threads. Closely concurrent producers can
have slightly different QPC and buffer insertion orders.

## Layers and interpretation

During a committed 0.9.151 mode transition, `render.present` reports the
DirectComposition scene commit HRESULT; ordinary frames still report swap-chain
Present. Frame summaries count CPU submissions, not every frame generated by
DWM's autonomous curves. A native dispatch gap can remain in those summaries
while the committed mode animation continues. `[GPU composition] MODE` marks
that path under either frame-time or performance logging.

| Operation | Information |
| --- | --- |
| `context`, `directory.context` | Tab/native HWND or directory generations, folder and initial geometry. |
| `dispatch.queue` | Message age before the mod's dispatch hook; `a` is the message and `b` its target HWND. |
| `dispatch.total`, `dispatch.native` | Whole dispatch hook versus the original Explorer dispatch, correlated by message/target. The difference includes hook work. |
| `overlay.message` | Every overlay callback, including sent messages, nested paint, timers and provider wakes; `a` is its message. |
| `input` | Processed input coordinates, message age and capture ownership. `a`/`b` are the Windows message/wParam. Wheel coordinates are screen coordinates; key messages retain their raw lParam words. |
| `pointer.sample` | Current captured gesture position, changed flag and capture ownership. `a=1` is a paced sample; `a=0` is mouse-message driven. `b` contains the state flags. These can advance a drag even when the input-message counter stays unchanged. Stationary samples do not restart easing. Button release or loss of capture stops sampling; the delivered release/capture messages own completion. |
| `scroll.thumb` | Mouse Y converted using the live scrollbar range/travel. |
| `scroll.retarget`, `scroll.immediate`, `scroll.step`, `scroll.stop`, `scroll.clamp` | Requested/previous destinations, current scroll, easing progress/delta, cancellation and range clamps. These expose motion resets even at a steady frame rate. |
| `frame.wake` | Posted-message queue delay, preceding DwmFlush duration and scroll position/target. `a` is the common compositor-cycle sequence. Gaps can include idle/unregistered cycles; inspect input/flags as well. Bit 32 of `b` indicates DwmFlush failure. |
| `frame.begin`, `frame.end` | Every paint interval without summary idle filtering. Begin `b` identifies the compositor wake, or zero for an unpaced/manual frame. End `b` is the producing UI thread's CPU-cycle delta, not milliseconds. |
| `frame.reentrant`, `frame.ack` | Nested paints and completion of the paced-paint latch. |
| `animation.advance` | Animation and paced-delivery advancement. |
| `frame.delivery`, `frame.demand`, `frame.upload`, `frame.draw`, `frame.flush`, `frame.present`, `frame.cleanup` | Individual frame-stage spans, even when normal frame summaries are disabled. |
| `render.layout` | Viewport width/height, row height and scrollbar range. |
| `cursor` | Physical cursor versus processed destination during a vertical grab. The expected destination is unsnapped; instant scrub can round it to rows. |
| `render.counts` | Per-frame text cache hits/misses/deferred cells and resident icons. |
| `render.endDraw`, `render.present` | Exact HRESULT in `a`. Present events include position/target, so accepted/rejected submissions can be distinguished from animation state advancement. These are submission diagnostics, not scan-out timestamps. |
| `viewport.demand`, `metadata.demand`, `icons.enqueue` | UI demand scans and actual icon requests; enqueue `a`/`b` are request ID/generation. |
| `directory.deliver`, `icons.deliver`, `metadata.apply` | Result delivery and metadata merges, including row/column generations. |
| `contention.directory`, `contention.icons` | Nonblocking UI delivery postponed because a provider owns its queue. |
| `view.mode.choose`, `view.mode.commit`, `view.mode.input` | Per-directory layout choice, first accepted content submission and actual user mode change. `a` is the folder token, `b` is the chosen/new mode. Choose values: cache hit, native-ready, pinned, icon size; commit: icon size and rows; input: prior native mode (0 for an explicit View command) and new icon size. |
| `worker.thumbnail.decorate` | Background thumbnail policy/resource resolution and one-texture film/badge assembly. Request ID and icon generation identify the owning job. Cached pixel drawing adds no provider work to Paint. |
| `worker.job`, `worker.icon`, `worker.publish`, `worker.icon.publish` | Worker job spans/publications, token/request IDs and result sizes. Icon scope end values are elapsed ms, queue ms and requested resolution. |
| `columns.fit`, `columns.transition`, `native.columns`, `native.presentation`, `native.selection` | Autofitting/transition entry and live Shell operations which can otherwise be hidden inside a callback. |
| `selection.import[index,next,restored,vacant]` | Changed native selection import: previous/current focused index and retained keyboard row/vacancy. `a` is the selected identity count and `b` the binding token. Performance logging separately reports recovered frame navigation as `[GPU selection] FRAME_KEY`. |
| `selection.retarget[from,to,tangent,rowHeight]`, `selection.frame[row,scroll,progress,tangent]`, `selection.stop[progress,fromRow]` | Keyboard highlight trajectory independently of logical/native selection. Tangents are document rows per 180 ms; frame progress is linear. Retargets preserve elapsed position and velocity, with a monotone clamp on reversals/shorter destinations. |
| `frame.yield.input[mask,pos,target,selection]` | A paced paint yields to input already in the owner thread's queue. `v[0]` is the current QS_INPUT mask; the held wake prevents another frame from outranking input before normal paint completes. Compare the next input's queue age and selection retarget with subsequent paint/ack. |
| `presentation.pending.*[kept,rows]` | Geometry, ownership, parent or suppression retry. Values show whether the GPU HWND remains visible and its row count; `a`/`b` identify native/pending HWNDs. Active GPU surfaces survive transient geometry/host handoffs. |
| `presentation.visibility[x,y,width,height]` | Actual GPU HWND visibility requests; `a` is WINDOWPOS flags (SHOW=0x40, HIDE=0x80), `b` its prior style. Position/size are meaningful only when the flags request those changes. |
| `native.suppress.event[hosts,viewports]` | A new native presentation host/viewport is acquired by the shared suppression barrier. `a` is CREATE/SHOW/PARENTCHANGE, `b` the triggering HWND. The process/thread-scoped synchronous event path acts before returning to native creation/show; ordinary lifecycle discovery stays queued. |
| `columns.composition.ready`, `columns.composition.upload`, `columns.composition.commit` | Mode-transition visual preparation, per-plane GPU copies and scene commit HRESULT. Ready records include header endpoints and canvas size; commit `b` indicates a previously published scene. Absolute-QPC DWM curves keep running between these CPU submissions. |
| `capacity.request` | Independent per-tab capacity generation (`a`), preserved directory/property generation (`b`), and target count (`v[0]`). Disk-space probes no longer invalidate unrelated names/property jobs. |

`worker.job` integer `a` uses the existing lane numbering: Directory=0, Layout=1,
Properties/reclamation=2, Icons=3, NativeRows=4, Selection=5, Columns=6,
IconProvider=7, Details=8, Capacity=9, Watch=10. Its `b` is the job generation;
scope-end values include elapsed ms, detail row index and request/entry count.

State flags used by scroll/frame/render events:

| Bit | State |
| --- | --- |
| 0–2 | Vertical animation, vertical grab, horizontal grab. |
| 3–5 | Metadata results, icon results, viewport demand pending. |
| 6–8 | Column transition, row transition, zoom animation. |
| 9–11 | Present retry, paced paint pending, native presentation pending. |
| 12–15 | Manipulation, marquee, supported scope, GPU mode enabled. |

Compare `input` → `scroll.thumb` → `scroll.retarget` → `scroll.step` → accepted
`render.present`. Stable timing with a repeated/reversing position suggests a
motion/ownership issue. A large queue age or span instead locates scheduling or
work that prevented that position from reaching a frame. The trace records the
evidence; it does not assume metadata fetching is the source of a visible stall.
